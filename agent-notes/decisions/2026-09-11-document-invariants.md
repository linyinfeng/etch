# D16 — 文档的结构不变量：让 lp 强制"先思路、后细节"（2026-09-11）

用户要求（原文）：

> 我要求 lp 强制要求 ai 以一种强逻辑一致性，重思路，渐进式披露的方式编写程序。

前置：D13（chunk 由声明给出，工具不解析 Typst）、D14（没有 `.typ` 行号，出处只到 chunk 级）、D10（未处置即错误）。铁规矩：能靠启发式/字符串搜索/重复解析实现的活，不做。

## 先划清边界：什么是工具能"强制"的

| | 属性 | 谁能保证 |
| --- | --- | --- |
| 机械可判定 | 名字在**被展开之前**先被引入（渐进式披露）、片段与它落进的根**语言一致**、引用图无环/无悬空、产出与声明一致（`--check`） | **`lp`（本 ADR，作为硬错误）** |
| 机械可判定（已有） | 输出目录里每个文件都被解释（D10）、未使用片段（警告） | `lp` |
| 只有写作者能保证 | 散文与代码语义一致、思路真的清楚、总结真的抓住了关键、论证不自相矛盾 | 写作者（人/agent）。`lp` **不引入 LLM**：它是确定性、离线的工具；语义审查由 agent 侧（skill）与 review 负责 |

这条边界必须写清楚：**"强制"指的是结构底线，不是"工具保证文章讲得对"**。

## D16.1 先命名后展开（渐进式披露）

- **定义位置**：声明流里第一次出现该名字的块的下标（同名声明拼接时取第一次）。
- **第一次引用位置**：按声明流顺序扫描每个块的正文，第一次出现独占一行的 `<<name>>` 的块下标。
- **规则**：`定义位置 < 第一次引用位置` → **错误**。也就是说：读者在前，细节在后；任何名字都必须先被某个已经读过的地方引入。
- 根（`#file`）同样受约束（它也能被引用），但通常不被引用，所以实际约束的是 `#chunk`。
- 文案指向声明（D14 没有行号）：报出名字、第一个引用它的块名、以及该声明正文的第一行。
- **为什么是错误而不是警告**：用户要求强制；而且这条规则的修复成本是"重排"，不是"重写"。
- **代价（接受）**：共享 preamble 之类"先集中定义、后使用"的写法不再允许——它必须出现在第一次引用之后。示例文档 `examples/demo/literate.typ` 与若干测试 fixture 因此需要重排（重排后更像骨架式文档，这是收益）。

## D16.2 语言一致

片段展开进某个根时，两边的 `lang` 都必须存在且相同；任一为空则跳过（空 = 未声明 = 不管）。

- 理由：`lang` 是文档里唯一关于"这段文本是什么"的声明。把 rust 片段塞进 python 文件是典型的自相矛盾，而它是**纯数据**可判定的。
- 错误文案：报出片段名、根的路径、两个 lang，以及引用它的块的行号。

## 落选方案

| 落选 | 为什么 |
| --- | --- |
| 用行数阈值/引用密度判"chunk 粒度"（例如"超过 N 行且无引用就报错"） | 阈值是任意的启发式；粒度是判断，不是判定。粒度靠 skill 的规范与 review |
| 解析 `.typ` 拿 heading 层级、用 `location()` 排序标题与声明 | 破 D13（不解析 Typst）；`location()` 依赖排版上下文，元数据元素未必有位置 |
| 把声明顺序改成"拓扑序自动排序" | 顺序就是叙述，是作者写的；工具不能替作者改故事 |
| 在 `lp` 里跑 LLM 做一致性审查 | 工具要保持确定性、离线、无外部依赖；语义审查属于 agent 侧 |
| 只做警告 | 与"强制"矛盾（用户明确要求） |

## 影响

- 结构底线变成三条硬错误（顺序、语言、引用图完整性）+ 已有所有权检查；一份"自上而下讲道理"的文档自然满足全部三条，一份"先把函数写齐再补文档"的文档会在第一条上失败。
- `examples/demo/literate.typ` 与 `tests/*` 的 fixture 要按新规则重排：这是采纳成本，也是这条规则有效的第一个证据。
- skill（`.agents/skills/literate-programming/`）必须写明：强制的是结构；语义自洽是你自己的责任，检查只能替你挡住漂移。
