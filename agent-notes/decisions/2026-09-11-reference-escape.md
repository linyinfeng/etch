# D17 — 转义：`@<<name>>` 输出字面量 `<<name>>`（2026-09-11）

前置：D15 决定 3 记下了这条升级路径（"若真有人在目标语言里需要这种行……再加转义——最小形状是行首 `@` 前缀"）。现在触发了。

## 触发它的事实

skill 本身要进文档（用户："所有一切都是 literate 的，最终 skill 也会进去"）。而 skill 的正文里必须**原样展示** `<<name>>` 独占一行的样子——那是它要教的东西。这些行进 `self.typ` 的 raw block 就会被当成引用：未声明 → 悬空报错；撞上同名 chunk → 静默替换成别的内容（更糟）。

同一类撞车已经出现过一次（D15 的测试夹具，用 `concat!` 绕开）。这次绕不开：要展示的就是那一行本身。

## 决定

- **语法**：一行若匹配 `^(\s*)@<<([^<>]+)>>\s*$`，tangle 输出 `<<name>>`（去掉 `@`，保留缩进）。其他位置（`@<<x>> y`、`@@<<x>>`）按普通文本处理。
- **作用范围**：tangle（`escaped_ref`）与 weave（包里的 `esc-re`，渲染成字面量而不是引用标记）。引用图、未使用片段的告警、D16.1 的先后顺序检查都**不把转义行算作引用**——它们本来就是文本。
- **代价**：多一个必须学的概念（一行 `@`）。用它的理由只有一个：文档在引用这套语法本身（skill、README、教学材料、`self.typ` 自身）。

## 落选

| 落选 | 为什么 |
| --- | --- |
| 给声明加 `literal: true` 标志（整块不展开） | 一刀切：一个文件里既想引用 chunk 又想展示 `<<name>>` 时无法表达；每行的意图才是真的意图 |
| 让未声明的 `<<x>>` 退化成字面量 | 会废掉最有用的一个错误（拼错的引用静默变成代码），D16 的强制也随之失效 |
| 在文档里把那一行改写掉（例如写成两个尖括号的说明） | 展示 `<<name>>` 独占一行正是要教的内容；写不了它，文档就在撒谎 |
| 长 fence / 别的转义字符（`\`、`%%`） | raw block 里没有转义处理；`@` 在行首 + `<<…>>` 的形状在真实代码里几乎不存在（与 D15 的撞车分析同源） |

## 影响

- 转写脚本（`experiments/2026-09-11-transliterate/self_typ.sh`）在嵌入文件时**自动给这类行加 `@`**；`--check` 绿即证明往返无失真（生成物里 `@` 被去掉，与原文件逐字节相同）。这就是"文档描述自己"所需的全部机制。
- `README.md`、`AGENTS.md`、skill 的机制一节要写上这一行；errors 表里"字面 `<<name>>` 消失"一条改成"用 `@<<name>>`"。
- **自举的拔升顺序**：冻结的种子只认识冻结时的语法，不认识 `@`。所以引入了新语法的这次变更在干净树上要两步：先用种子 tangle（代码部分正确，引用了转义语的 `.md` 会带上 `@`）→ `cargo build` 得到认识转义的二进制 → 再 tangle 一次（`--check` 才绿）。以后再加语法同理。
- 单测：`escaped_ref` 的形状测试（在 `tangle.rs` 的单元测试里）+ `--check` 的往返。

## 验证

```sh
nix develop -c cargo test                     # 含转义的单测与往返
nix develop -c ./target/debug/lp tangle self.typ --out . --check
nix develop -c examples/demo/run.sh
```
