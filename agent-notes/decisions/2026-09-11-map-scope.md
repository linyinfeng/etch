# 行号映射的作用域：每个目录一份（2026-09-11）

## D11 — `.lpmap.json` 按目录拆分，渐进式披露

- **决定**：每个输出目录里放一份 `.lpmap.json`，**只管该目录下直接躺着的文件**（`out/src/.lpmap.json` 只列 `src/` 里的）。键是**文件名**（不再是相对 `--out` 的路径）。查询时按**最具体的目录优先**解析；只给文件名而多个目录同名时，报歧义、不猜。目录不再产出任何东西时，它的映射随目录一起消失。
- **落选**：
  - 根部一份全局索引（原实现），键是完整相对路径。否决理由：一个目录的元数据住在根上，读它要面对整棵树的索引；子树被删/被移动时那份索引不会跟着走（会留下描述已不存在文件的条目），需要额外的失效逻辑。
  - 根索引 + 子目录索引两层（"按需下钻"）：两套查找路径、两份真相，收益不明。
- **理由（渐进式披露）**：
  1. **读的粒度 = 关心的粒度**：人在（或 agent 在）`src/` 里干活，只读 `src/.lpmap.json`，不必先理解整棵树。
  2. **映射跟着它解释的文件走**：移动/删除子树就是移动/删除它的映射，不需要全局失效逻辑。
  3. **和 `.lpignore` 同一个心智模型**：元数据住在它作用的那个目录里。
  4. **歧义显式化**：`--file main.rs` 命中多个目录时报错而不是随便挑一个 —— 对 agent 尤其重要。
- **代价**：
  - 反向查询（`--typ`）要遍历 `--out` 下所有映射（一次 walk），比读单个文件贵；实测规模下无所谓。
  - 诊断路径的解析多了一步"哪个目录"，但它用观察到的路径做后缀匹配（`build/src/main.rs` 命中 `src/`），三种常见写法（相对 `--out`、相对 cwd、绝对）都能用。
  - 版本号升到 2：键的语义变了（文件名而非路径）。没有发布过用户，不做迁移。
- **回归**：`tests/flow.rs`（映射落在正确目录、根映射不索引子树、路径/裸名解析、歧义报错、反向输出带目录）、`tests/owned.rs`（映射随目录消失）。
