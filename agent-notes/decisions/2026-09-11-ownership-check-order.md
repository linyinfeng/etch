# D20 — 所有权检查移到写盘之后（2026-09-11）

前置：D10（未处置即错误）、D19（构建与控制文件也属于文档，`.lpignore` 成为生成物）。

## 决定

`lp tangle` 里"输出目录里每个文件都要被解释"的检查，从**读盘之后、写盘之前**移到**写文件之后、写 mapping 之前**。

## 为什么

D19 要求 `.lpignore` 由文档声明。但一个干净仓库里 `.lpignore` 还不存在：如果检查仍然先跑，第一遍（种子那遍）就会以"未处置"拒绝，仓库**无法自举**。检查放在写盘之后就顺理成章——这一遍刚把控制文件写下去，随后的 walk 读到的就是真实的事后状态。

## 丢掉了什么（接受的代价）

以前"树不合法 → 一个字节都不写"；现在会先刷新文档声明的文件、再报"未处置"。

- `lp` 从不自行删除（D10），写盘只写变化的字节（D9），所以影响面是"这一遍本来就要更新的文件被更新了"。
- 未处置的多半是别的东西（生成物、别人的产物），改 `.lpignore` 或显式删掉即可；报错内容与出路不变。

## 落选

| 落选 | 为什么 |
| --- | --- |
| 让 `.lpignore` 继续做手写 tracked 资产 | 可行，但控制文件就有了两份真相（tracked 一份 + 文档声明一份），正是 D4 想避免的形态 |
| 检查时跳过"这一遍会产出的文件" | 特例化：检查不再是"看状态"，而是"看状态 + 这一遍的意图"，以后每加一个生成的控制文件都要再特例一次 |
| 让 walker 知道"这个子树是另一个文档的产物" | 那是新特性；`.lpignore` 已经能表达这个边界（本仓库就用它把演示目录交给演示文档，见根 `.lpignore` 里 `/examples/demo/build`） |

## 验证

```sh
nix develop -c cargo test                                  # owned / lazy / self 三套都覆盖所有权与写盘行为
nix develop -c ./target/debug/lp tangle lp.typ --out . --check
git clone . /tmp/fresh && cd /tmp/fresh                    # 干净仓库自举：见 README §自举
```
